Mission roverDémarche technologique

Comment programmer le rover ?

Je vais compléter un programme structuré en sous-programmes, avec démarrage et arrêt par boutons, puis le mettre au point.

5′Problème10′Analyser5′Retenir30′Réaliser5′Bilan
🎯 Ce que je vais apprendre

Objectif : Je vais compléter un programme structuré en sous-programmes, avec démarrage et arrêt par boutons, puis le mettre au point.

Je réussis si : Le rover démarre avec A, s’arrête avec B, contourne un obstacle placé devant lui et affiche « ? » quand la mesure est impossible.

5′

1. Le problème à résoudre

L’algorigramme est prêt et le rover est assemblé.

Comment traduire l’algorigramme en programme ?

10′

2. Analyser : Lire le programme de départ

Le programme ci-dessous (MakeCode, mode JavaScript) suit l’algorigramme. Les lignes marquées « À COMPLÉTER » dépendent de votre robot.

Programme

// Rover autonome — programme structuré (3e)
// Extension MakeCode nécessaire : « sonar » (capteur à ultrasons : trig sur P1, echo sur P2)
let SEUIL = 15          // distance (cm) en dessous de laquelle le rover contourne
let enMission = false   // état du rover : en mission ou à l'arrêt
let distance = 0

// ----- Sous-programmes -----
function mesurerDistance(): number {
    return sonar.ping(DigitalPin.P1, DigitalPin.P2, PingUnit.Centimeters)
}
function avancer() {
    // À COMPLÉTER : blocs moteurs de votre robot, les deux roues en avant, vitesse modérée
}
function arreter() {
    // À COMPLÉTER : blocs moteurs de votre robot, les deux roues à l'arrêt
}
function contourner() {
    arreter()
    basic.pause(300)
    // À COMPLÉTER : tourner sur place vers la gauche
    basic.pause(400)
    arreter()
}

// ----- Interaction humain-machine -----
input.onButtonPressed(Button.A, function () {   // A : démarrer la mission
    enMission = true
    basic.showIcon(IconNames.Happy)
})
input.onButtonPressed(Button.B, function () {   // B : arrêter la mission
    enMission = false
    arreter()
    basic.showIcon(IconNames.No)
})

// ----- Boucle de décision -----
basic.forever(function () {
    if (enMission) {
        distance = mesurerDistance()
        if (distance == 0) {
            arreter()                 // pas d'écho : arrêt de sécurité
            basic.showString("?")
        } else if (distance < SEUIL) {
            contourner()
        } else {
            avancer()
        }
        serial.writeLine("" + distance)   // trace des mesures pour l'analyse
    }
    basic.pause(50)
})

Je réponds

5′

3. Je retiens

Trace écrite

Un programme structuré regroupe les actions dans des sous-programmes, appelés par leur nom. La boucle principale lit les capteurs, décide et agit. Une interaction humain-machine (boutons, affichage) permet de démarrer, d’arrêter et de suivre l’état du système.

30′

4. Je réalise : Compléter, tester, mettre au point

Complète les sous-programmes moteurs pour votre robot, puis teste chaque fonction séparément avant l’essai complet.

  1. Ajoute l’extension « sonar » dans MakeCode.
  2. Complète avancer, arreter et contourner avec les blocs moteurs de votre robot.
  3. Test 1 : A puis B, le rover démarre puis s’arrête.
  4. Test 2 : un carton à 30 cm, puis à 10 cm devant le rover.
  5. Test 3 : capteur masqué par la main très près, puis retiré ; observe la trace dans la console série.
  6. Ajuste les durées de contournement et commente tes modifications.

Ce que je dois produire : Programme complété, commenté et testé ; fiche des trois tests.

Matériel : Rover assemblé, câble USB, ordinateur avec MakeCode (ou mBlock pour un mBot).

Besoin d’un coup de pouce ?

Teste toujours un sous-programme seul avant de l’utiliser dans la boucle.

Correction (pour l’enseignant)

Objectif : Traduire l’algorithme en programme structuré ; réaliser un programme commandant un système réel avec interaction humain-machine.

Programme : Repères de 3e : programme structuré (sous-programmes ou fonctions) ; « Réaliser et mettre au point un programme commandant un système réel incluant une interaction entre un humain et une machine ».

Déroulé : Problème 5 min ; Analyser 10 min ; Retenir 5 min ; Réaliser 30 min ; Bilan 5 min.

Réponses de l’enquête

  1. Quels sous-programmes le programme définit-il ? mesurerDistance, avancer, arreter et contourner.
  2. Quelle partie du programme réalise l’interaction humain-machine ? Les blocs des boutons A (démarrer) et B (arrêter), et l’affichage des icônes.
  3. Que fait le rover si la mesure vaut 0 ? Il s’arrête et affiche « ? » : c’est l’arrêt de sécurité.

Production attendue

Les trois tests sont réussis et notés ; les durées de contournement sont ajustées ; les modifications sont commentées.

QCM

  1. Dans ce programme, le bouton B… Réponse B : arrête la mission et les moteurs. B met enMission à false et appelle arreter().
  2. Pourquoi tester chaque sous-programme séparément ? Réponse B : pour localiser plus facilement une erreur. On isole les causes possibles d’un défaut.

Point de vigilance : Pour un mBot, utiliser mBlock : les blocs équivalents existent (capteur à ultrasons, moteurs) ; garder la même structure en sous-programmes.

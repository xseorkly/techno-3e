Éviter sans bloquer le programme

Comment continuer à surveiller le robot pendant une manœuvre ?

En une phrase

Le robot avance ; face à un obstacle il recule puis tourne, sans longues pauses : le programme sait toujours dans quelle phase il est.

Durée estimée
40 min
Difficulté
●●●
Matériel
Maqueen avec ultrason, zone dégagée, carton
Lancement
A active, B arrête

À la fin, je saurai :

  • Je sais décrire un comportement avec des états.
  • Je comprends pourquoi une longue « pause » bloque la surveillance.
① Prédire

Avant de regarder le programme

Répondez par écrit (une phrase suffit). Se tromper ici est utile : c’est ce qui fait apprendre.

  1. Pendant un « pause 300 ms », le robot lit-il ses boutons ?
  2. Combien de phases distinctes y a-t-il dans la manœuvre ?
② Le programme, bloc par bloc

Ce que fait chaque bloc

Un programme est un empilement de blocs, à lire de haut en bas. La couleur d’un bloc indique son rôle. Chaque bloc est expliqué dans l’ordre.

DépartContrôleMoteursCapteurAffichage / LEDMémoireCalculMa fonctionCommunication

Les blocs ci-dessous sont redessinés pour être lisibles ; la vraie capture de MakeCode est plus bas. Les libellés peuvent différer légèrement selon la version de MakeCode.

Le programme

1
Stop le moteur Tous ▾Moteurs

Ce que fait ce bloc : Coupe les deux moteurs : les roues cessent de tourner.

Pourquoi il est là : Placé au démarrage, il garantit que le robot ne partira pas tout seul quand on l’allume. C’est une règle de sécurité à toujours mettre en premier.

2
définir etat ▾ à 0Mémoire

Ce que fait ce bloc : Mémorise la phase du robot : 0 = avancer, 1 = reculer, 2 = tourner.

Pourquoi il est là : L’état est la « phase en cours » : le programme sait où il en est.

Mot à connaître. Une machine à états est un programme organisé en phases, avec des règles pour passer de l’une à l’autre.

3
définir debut ▾ à 0Mémoire

Ce que fait ce bloc : Mémorise l’heure à laquelle la phase a commencé.

Pourquoi il est là : Remplace la pause : on compare l’heure actuelle à ce début.

4
lorsque le bouton A ▾ est presséDépart

Ce que fait ce bloc : Active le robot et revient à l’état 0.

Pourquoi il est là : Départ de la manœuvre.

Mot à connaître. Les boutons A et B sont les deux boutons physiques de la carte micro:bit (sur la face avant, de part et d’autre de la matrice de LED).

5
lorsque le bouton B ▾ est presséDépart

Ce que fait ce bloc : Désactive et arrête.

Pourquoi il est là : Arrêt possible à tout moment.

Mot à connaître. Les boutons A et B sont les deux boutons physiques de la carte micro:bit (sur la face avant, de part et d’autre de la matrice de LED).

6
toujoursContrôle

Ce que fait ce bloc : Répète sans fin les tests ci-dessous.

Pourquoi il est là : Boucle rapide : elle ne contient aucune longue pause.

7
si etat = 0 alors (avancer ou détecter)Contrôle

Ce que fait ce bloc : Mesure ; si obstacle ≤ 20, passe à l’état 1 ; sinon avance.

Pourquoi il est là : Phase de surveillance.

8
si etat = 1 et temps d’exécution − debut ≥ 300Contrôle

Ce que fait ce bloc : Après 300 ms de recul, passe à l’état 2 et commence le pivot.

Pourquoi il est là : Le temps écoulé se calcule avec « temps d’exécution (ms) ».

Mot à connaître. « temps d’exécution (ms) » donne le nombre de millisecondes écoulées depuis l’allumage.

9
si etat = 2 et temps d’exécution − debut ≥ 400Contrôle

Ce que fait ce bloc : Après 400 ms de pivot, arrête et revient à l’état 0.

Pourquoi il est là : Fin du cycle.

10
pause (ms) 20Contrôle

Ce que fait ce bloc : Le programme attend 20 millisecondes (soit 0.02 seconde). Pendant ce temps, les moteurs gardent le dernier ordre reçu.

Pourquoi il est là : Cadence courte.

Mot à connaître. 1000 millisecondes (ms) = 1 seconde.

Le programme en français

Le même programme, avec des phrases

Les lignes décalées vers la droite sont à l’intérieur d’une répétition ou d’une condition.

A active et met l’état à 0 ; B arrête.
Toujours, toutes les 20 ms, si actif :
   état 0 : je mesure ; obstacle → état 1 (recul) ; sinon j’avance ;
   état 1 : après 300 ms → état 2 (pivot) ;
   état 2 : après 400 ms → arrêt et retour à l’état 0.
Dans MakeCode

Le vrai programme

Voir le code en texte (JavaScript)
maqueen.motorStop(maqueen.Motors.All)
let actif = false
let etat = 0
let debut = 0
let distance = 0
input.onButtonPressed(Button.A, function () {
etat = 0
actif = true
})
input.onButtonPressed(Button.B, function () {
actif = false
maqueen.motorStop(maqueen.Motors.All)
})
basic.forever(function () {
if (actif) {
if (etat == 0) {
distance = maqueen.Ultrasonic()
if (distance <= 0 || distance >= 500) {
actif = false
maqueen.motorStop(maqueen.Motors.All)
} else if (distance <= 20) {
etat = 1
debut = input.runningTime()
maqueen.motorRun(maqueen.Motors.All, maqueen.Dir.CCW, 60)
} else {
maqueen.motorRun(maqueen.Motors.All, maqueen.Dir.CW, 60)
}
} else if (etat == 1) {
if (input.runningTime() - debut >= 300) {
etat = 2
debut = input.runningTime()
maqueen.motorRun(maqueen.Motors.M1, maqueen.Dir.CW, 60)
maqueen.motorRun(maqueen.Motors.M2, maqueen.Dir.CCW, 60)
}
} else if (input.runningTime() - debut >= 400) {
maqueen.motorStop(maqueen.Motors.All)
etat = 0
}
}
basic.pause(20)
})
③ Essayer

Testez pas à pas

  1. Comparez l’effet de B pendant la manœuvre ici et dans l’activité 8.
  2. Observez avance, recul, pivot, nouvelle mesure.
  3. Retirez la cible : que fait le robot ?
Ce que vous devez observer : B répond aussitôt, même en plein recul : le programme n’est pas bloqué par une pause.

Si ça ne marche pas

  • Le robot ne repart pas. Après un stop sur mesure invalide, relancez avec A.

Autres solutions : page Aide. Les programmes n’ont pas été essayés sur un robot réel ici : vos observations peuvent différer légèrement. Roues levées pour les premiers essais, puis sol dégagé.

④ Expliquer

Modifiez une chose, prévoyez, vérifiez

Changez un seul élément, écrivez ce que vous pensez voir, puis vérifiez avec le robot. Si vous savez expliquer l’écart entre prévision et observation, vous avez compris.

  • Modifiez une durée de transition et testez uniquement cette phase.

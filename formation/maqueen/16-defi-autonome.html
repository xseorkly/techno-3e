Défi : le robot de livraison

Comment reconnaître l’arrivée sans confondre un virage avec la fin ?

En une phrase

Le robot suit la piste, s’arrête devant un obstacle, et s’arrête à l’arrivée (zone blanche) en affichant une coche.

Durée estimée
45 min
Difficulté
●●●
Matériel
Maqueen complet, piste noire large finissant sur une zone blanche, obstacles
Lancement
A active, B arrête

À la fin, je saurai :

  • Je sais assembler plusieurs règles dans un programme complet.
  • Je sais critiquer un critère d’arrivée.
① Prédire

Avant de regarder le programme

Répondez par écrit (une phrase suffit). Se tromper ici est utile : c’est ce qui fait apprendre.

  1. Comment le robot peut-il savoir qu’il est arrivé ?
  2. Peut-il confondre une ligne perdue et l’arrivée ?
② Le programme, bloc par bloc

Ce que fait chaque bloc

Un programme est un empilement de blocs, à lire de haut en bas. La couleur d’un bloc indique son rôle. Chaque bloc est expliqué dans l’ordre.

Le programme

1
Stop le moteur Tous ▾Moteurs

Ce que fait ce bloc : Coupe les deux moteurs : les roues cessent de tourner.

Pourquoi il est là : Placé au démarrage, il garantit que le robot ne partira pas tout seul quand on l’allume. C’est une règle de sécurité à toujours mettre en premier.

2
définir actif ▾ à fauxMémoire

Ce que fait ce bloc : Le robot attend A.

Pourquoi il est là : Interrupteur logiciel.

3
lorsque le bouton A ▾ est presséDépart

Ce que fait ce bloc : Active et remet le chronomètre d’arrivée à zéro.

Pourquoi il est là : Lance la livraison.

Mot à connaître. Les boutons A et B sont les deux boutons physiques de la carte micro:bit (sur la face avant, de part et d’autre de la matrice de LED).

4
lorsque le bouton B ▾ est presséDépart

Ce que fait ce bloc : Désactive et arrête.

Pourquoi il est là : Arrêt manuel.

Mot à connaître. Les boutons A et B sont les deux boutons physiques de la carte micro:bit (sur la face avant, de part et d’autre de la matrice de LED).

5
toujoursContrôle

Ce que fait ce bloc : Répète sans fin.

Pourquoi il est là : Surveillance continue.

6
si actif alorsContrôle

Ce que fait ce bloc : Ne fait rien tant qu’on n’a pas appuyé sur A.

Pourquoi il est là : Le robot attend.

7
obstacle ou mesure invalide → arrêt et actif = fauxContrôle

Ce que fait ce bloc : Sécurité d’abord.

Pourquoi il est là : L’obstacle a la priorité.

8
blanc/blanc → arrêt, on chronomètreContrôle

Ce que fait ce bloc : Les deux capteurs voient du blanc : arrivée ou ligne perdue ?

Pourquoi il est là : Le robot ne peut pas distinguer les deux.

9
si temps d’exécution − debutBlanc ≥ 500 → coche et actif = fauxContrôle

Ce que fait ce bloc : Après 500 ms consécutives de blanc, il déclare l’arrivée.

Pourquoi il est là : On évite qu’un blanc très bref soit pris pour l’arrivée.

10
montrer l’icône coche ▾Affichage / LED

Ce que fait ce bloc : Affiche la coche d’arrivée.

Pourquoi il est là : Signal visible.

11
sinon : suivre la ligne (activité 10)Contrôle

Ce que fait ce bloc : Applique la table de suivi de ligne.

Pourquoi il est là : Comportement normal.

Le vrai programme

Télécharger le programme (.hex)Code en texte (.ts)
Voir le code en texte (JavaScript)
maqueen.motorStop(maqueen.Motors.All)
let actif = false
let gauche = 0
let droite = 0
let distance = 0
let debutBlanc = 0
input.onButtonPressed(Button.A, function () {
actif = true
debutBlanc = 0
})
input.onButtonPressed(Button.B, function () {
actif = false
maqueen.motorStop(maqueen.Motors.All)
})
basic.forever(function () {
if (actif) {
distance = maqueen.Ultrasonic()
gauche = maqueen.readPatrol(maqueen.Patrol.PatrolLeft)
droite = maqueen.readPatrol(maqueen.Patrol.PatrolRight)
if (distance <= 0 || distance >= 500 || distance <= 20) {
maqueen.motorStop(maqueen.Motors.All)
actif = false
} else if (gauche == 1 && droite == 1) {
maqueen.motorStop(maqueen.Motors.All)
if (debutBlanc == 0) {
debutBlanc = input.runningTime()
}
if (input.runningTime() - debutBlanc >= 500) {
actif = false
basic.showIcon(IconNames.Yes)
}
} else {
debutBlanc = 0
gauche = maqueen.readPatrol(maqueen.Patrol.PatrolLeft)
droite = maqueen.readPatrol(maqueen.Patrol.PatrolRight)
if (gauche == 0 && droite == 0) {
maqueen.motorRun(maqueen.Motors.All, maqueen.Dir.CW, 60)
} else if (gauche == 0 && droite == 1) {
maqueen.motorRun(maqueen.Motors.M1, maqueen.Dir.CW, 0)
maqueen.motorRun(maqueen.Motors.M2, maqueen.Dir.CW, 60)
} else if (gauche == 1 && droite == 0) {
maqueen.motorRun(maqueen.Motors.M1, maqueen.Dir.CW, 60)
maqueen.motorRun(maqueen.Motors.M2, maqueen.Dir.CW, 0)
} else {
maqueen.motorStop(maqueen.Motors.All)
}
}
}
basic.pause(20)
})
③ Essayer

Testez pas à pas

  1. Réalisez une piste noire finissant sur une zone blanche.
  2. Testez séparément : arrivée, perte accidentelle, obstacle, bouton B.
  3. Montrez qu’une perte de ligne durable produit aussi la coche : discutez le critère.
Ce que vous devez observer : Le robot suit la ligne, s’arrête devant un obstacle, et affiche la coche en fin de piste ou après une perte persistante.

Si ça ne marche pas

  • Le robot s’arrête dans un virage. Virage trop serré : élargissez-le ou ralentissez.

Preuve de livraison. Une zone blanche ou une perte de ligne arrête aussi le robot : un simple arrêt ne prouve donc pas la livraison. Gardez le test de perte accidentelle de ligne (soulevez le robot ou coupez la piste) et imposez un second indice pour valider la livraison, par exemple un repère de couleur au bout du parcours ou un appui de B après arrivée. Discutez : quelle preuve distingue une livraison réussie d’une perte de ligne ?

④ Expliquer

Changez un seul élément, écrivez ce que vous pensez voir, puis vérifiez avec le robot. Si vous savez expliquer l’écart entre prévision et observation, vous avez compris.

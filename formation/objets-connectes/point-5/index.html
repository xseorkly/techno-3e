Point 5 · expérimentation

Commander un actionneur depuis ThingSpeak

Vous savez déjà envoyer une donnée de capteur vers ThingSpeak. Ici, vous allez inverser le sens : une commande créée dans ThingSpeak sera lue par la micro:bit, puis transformée en action physique sur la REKA:BIT.

Commencer l’expérimentation ↓ Télécharger l’extension expérimentale (.zip)
Objectif : construire une chaîne bidirectionnelle. Un champ ThingSpeak contient une consigne 0 / 1. Un bouton écrit la consigne. La micro:bit lit la dernière valeur via le Grove WiFi 8266, puis commande un actionneur : moteur, LED, servo ou relais adapté.

2. Repérer le matériel et les ports

Branchement conseillé pour le premier essai : Grove WiFi 8266 sur le port P15:P16. Pour l’actionneur, utilisez soit un petit moteur DC sur M1, soit un module LED basse tension sur le signal P0 du port Grove P0:P1.
Sécurité : n’alimentez jamais une lampe secteur ou un moteur de puissance directement depuis une broche micro:bit. Pour une charge plus importante, utilisez un driver, un MOSFET ou un relais correctement isolé et une alimentation adaptée. Pas de 230 V dans cette expérimentation.

3. Créer le champ de commande dans ThingSpeak

01

Ajouter un champ « Commande »

Ouvrez votre canal ThingSpeak, puis Channel Settings. Nommez un champ libre, par exemple Field 4 — Commande actionneur. Enregistrez.

02

Choisir une convention simple

Nous utiliserons : 0 = arrêt et 1 = marche. Cette convention constitue déjà un mini‑protocole de commande.

03

Repérer les clés API

Dans API Keys, repérez la Write API Key pour écrire la commande et la Read API Key si votre canal est privé.

4. Créer deux boutons directement dans ThingSpeak

Dans ThingSpeak, ouvrez Apps → Plugins → New, choisissez un plugin personnalisé puis associez‑le à votre canal privé. Le plugin ci‑dessous crée deux boutons : MARCHE et ARRÊT.

HTML

<div class="commande">
  <h3>Commande à distance</h3>
  <button class="on" onclick="envoyer(1)">ALLUMER / DÉMARRER</button>
  <button class="off" onclick="envoyer(0)">ÉTEINDRE / ARRÊTER</button>
  <p id="etat">Prêt.</p>
</div>

JavaScript

const WRITE_KEY = "VOTRE_WRITE_API_KEY";
const FIELD = 4;

function envoyer(valeur) {
  const url =
    "https://api.thingspeak.com/update?api_key=" +
    WRITE_KEY + "&field" + FIELD + "=" + valeur;

  const xhr = new XMLHttpRequest();
  xhr.open("GET", url, true);
  xhr.send();
}
À observer : sur l’offre gratuite ThingSpeak, les écritures sont espacées d’environ 15 secondes. Ce système est donc une commande à distance, pas une télécommande temps réel. Cette limite fait partie de l’expérimentation.

5. Ajouter l’extension MakeCode expérimentale

Extension ThingSpeak RX — V0.1

Cette extension complète l’extension Cytron ESP8266 avec un bloc de lecture de la dernière valeur d’un champ ThingSpeak.

Télécharger l’extension

Important : cette version est expérimentale et n’est pas garantie à 100 %. Elle doit être testée sur le Grove WiFi 8266 réel. Selon le firmware ESP‑AT, une petite adaptation peut être nécessaire.

Bloc principal

lire ThingSpeak canal [ID] champ [1..8] clé lecture [KEY]

Le bloc interroge la dernière valeur du champ puis renvoie un nombre. Un autre bloc indique si la lecture a réussi.

6. Programmer la lecture de la commande

Logique générale

AU DÉMARRAGE
  initialiser ESP8266 : Tx P16 / Rx P15 / 115200
  se connecter au Wi‑Fi

TOUJOURS
  commande ← lire ThingSpeak canal ID champ 4 clé READ_API_KEY

  SI lecture réussie
      SI commande = 1
          activer l’actionneur
      SINON
          arrêter l’actionneur

  attendre 2 secondes

8. Tester couche par couche

A

Wi‑Fi

Vérifiez d’abord que l’ESP8266 est initialisé et connecté.

B

ThingSpeak

Écrivez manuellement 0 puis 1 dans le champ et vérifiez l’historique.

C

Lecture

Affichez d’abord la valeur 0 ou 1 sur la matrice micro:bit.

D

Action

Seulement après, branchez M1, P0 ou S1 et testez le comportement.

9. Ce que cette expérimentation permet de comprendre

Un IoT bidirectionnel

Le cloud n’est plus seulement un lieu où l’on envoie des mesures : il devient aussi une source de consigne.

Donnée, information, commande

Une température mesurée et une valeur 0/1 sont toutes deux des données, mais elles n’ont pas le même rôle dans le système.

API REST

Une URL devient concrètement un moyen d’écrire ou de lire une valeur distante.

Protocole

La convention 0/1 est un protocole minimal. Elle peut être enrichie : vitesse, angle, intensité, mode de fonctionnement.

Latence et temps réel

Vous pouvez mesurer le délai entre le clic et l’action et comprendre pourquoi tous les systèmes connectés ne sont pas temps réel.

Chaîne d’information / chaîne d’énergie

La valeur numérique commande l’action, mais la puissance nécessaire au moteur est fournie par une autre chaîne.

Cybersécurité

La Read API Key et la Write API Key n’accordent pas les mêmes droits. Une clé d’écriture exposée permettrait de commander le système.

Diagnostic

Cloud, Wi‑Fi, UART, programme, port, actionneur : chaque couche peut être testée séparément.

À retenir : le défi technique est volontairement simple. L’intérêt est de rendre visibles les choix d’architecture, la circulation de l’information, la notion de commande distante, les limites de la plateforme et les stratégies de mise au point.

Point 2 — Faire circuler la donnée jusqu’à ThingSpeak

Une démarche technique pensée pour les enseignants : comprendre chaque étape avant de la reproduire avec les élèves.

Question de départ

Que se passe-t-il réellement entre le capteur et le graphique affiché dans un navigateur ?

Capteur→micro:bit→UART→ESP8266→Wi‑Fi→HTTP/API→ThingSpeak→HTML

Cette seconde partie ouvre la « boîte noire » : connexion réseau, clé d’écriture, envoi des valeurs et récupération pour affichage.

Étape 1

Préparer MakeCode

Dans Microsoft MakeCode pour micro:bit, ajouter l’extension Cytron ESP8266. Elle fournit les blocs d’initialisation du module, de connexion Wi‑Fi et d’envoi vers ThingSpeak.

Extension : CytronTechnologies/pxt-esp8266
Étape 2

Initialiser la liaison série

Le module Wi‑Fi est connecté sur le port Grove P15:P16. Dans le programme, on indique donc P16 comme TX et P15 comme RX, avec le débit documenté par Cytron.

Initialiser ESP8266
TX = P16
RX = P15
Baudrate = 115200

Le premier test consiste uniquement à vérifier que la micro:bit communique avec l’ESP8266. On ne cherche pas encore à envoyer des données sur Internet.

Étape 3

Connecter l’objet au Wi‑Fi

Le programme fournit au module le nom du réseau (SSID) et son mot de passe. Pour une formation, un point d’accès 2,4 GHz dédié est souvent plus fiable qu’un réseau d’établissement utilisant portail captif ou authentification complexe.

connect WiFi
SSID = "Reseau_Formation"
Mot de passe = "********"
Objectif pédagogique : distinguer être relié au module Wi‑Fi et être effectivement connecté à Internet.
Organisation enseignant

Deux comptes ThingSpeak pour les postes de travail

Avec deux comptes professionnels distincts, l’enseignant peut répartir ses canaux entre les deux espaces. L’intérêt est que les élèves n’ont pas besoin de créer de compte personnel : ils travaillent avec les paramètres fournis pour leur groupe.

Compte enseignant ACompte enseignant B
Canaux groupes 1 à 4Canaux groupes 5 à 7
L’enseignant conserve les identifiants du compteL’enseignant conserve les identifiants du compte
Chaque groupe reçoit seulement son Channel ID et sa Write API KeyChaque groupe reçoit seulement son Channel ID et sa Write API Key

Les clés affichées sur la page de formation devront être des exemples. Ne jamais publier les vraies Write API Keys dans un dépôt GitHub public.

Étape 4

Créer un canal ThingSpeak

1 — New Channel

Créer un canal pour un groupe ou un poste.

2 — Nommer les champs

Exemple : Field 1 = température, Field 2 = humidité, Field 3 = CO₂.

3 — Enregistrer

ThingSpeak fournit un identifiant de canal.

4 — API Keys

Récupérer la Write API Key pour l’écriture. La Read API Key ne sert que si le canal reste privé et doit être lu via API.

Un canal ThingSpeak peut contenir jusqu’à huit champs de données. Pour une première séance, trois champs suffisent largement : température, humidité et CO₂.

Étape 5

Envoyer une première donnée

Avant d’utiliser un vrai capteur, il est préférable d’envoyer une valeur fixe. Cela permet de valider séparément le Wi‑Fi, Internet, l’API et ThingSpeak.

Upload data to ThingSpeak
Write API Key = "VOTRE_CLE_ECRITURE"
Field 1 = 22
Field 2 = 48
Field 3 = 650

Si les valeurs apparaissent sur le canal, la chaîne de communication fonctionne. On pourra ensuite remplacer 22, 48 et 650 par de vraies mesures.

Étape 6

Passer de la valeur de test à la vraie mesure

La logique générale du programme devient :

Au démarrage
  initialiser ESP8266
  se connecter au Wi‑Fi

Toutes les 20 secondes environ
  température = lire capteur
  humidité = lire capteur
  CO2 = lire capteur
  envoyer température, humidité, CO2 vers ThingSpeak
On sépare ainsi clairement : acquisition → traitement → transmission.
Étape 7

Rendre la donnée visible sans compte élève

Deux solutions sont possibles.

Canal public

Les élèves peuvent consulter directement les graphiques publics sans créer de compte.

Page HTML de l’établissement

Notre solution cible : une page du site récupère les données de ThingSpeak et affiche les mesures des différents groupes dans une interface commune.

micro:bit → ESP8266 → ThingSpeak → API de lecture → page HTML du site

Dans la prochaine étape, nous construirons précisément cette page de visualisation, avec les 7 postes et les deux comptes enseignant.

Questions aux collègues

Avant de passer au TP

  1. Pourquoi tester d’abord avec une valeur fixe plutôt qu’avec un capteur ?
  2. Quelle différence entre SSID, Channel ID et Write API Key ?
  3. Pourquoi ne doit-on pas publier une Write API Key sur le site ?
  4. Quelle partie de l’architecture fonctionne encore si Internet est coupé ?
  5. Pourquoi conserver un délai entre deux envois ?

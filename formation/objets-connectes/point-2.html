Point 2 — Faire circuler la donnée jusqu’à ThingSpeak

Tutoriel pas à pas : on avance comme une recette de cuisine, en vérifiant le résultat à chaque étape.

Avant de commencer

Ce que nous allons réussir à faire

micro:bit→REKA:BIT→ESP8266→Wi‑Fi→ThingSpeak

À la fin, une valeur envoyée par la micro:bit apparaîtra dans un graphique ThingSpeak. Nous commencerons volontairement par une valeur fixe avant de connecter un vrai capteur.

Étape 1 — Préparer le matériel

Posez exactement ceci sur la table

1 micro:bit V2

La carte qui exécutera le programme MakeCode.

1 REKA:BIT

Elle accueille la micro:bit, fournit les ports Grove et une alimentation plus robuste.

1 Grove WiFi 8266

Le module qui connectera le système au réseau Wi‑Fi.

1 câble Grove + alimentation

Le câble relie le module Wi‑Fi à la REKA:BIT. Prévoir une alimentation stable pour la REKA:BIT.

À ce stade, ne branchez encore aucun capteur : nous voulons d’abord valider la communication et Internet.
Étape 2 — Réaliser le branchement

Branchez le module Wi‑Fi sur P15:P16

1. Insérez la micro:bit dans la REKA:BIT.

2. Repérez le connecteur Grove marqué P15:P16.

3. Branchez un seul câble Grove entre ce port et le Grove WiFi 8266.

4. Alimentez la REKA:BIT puis mettez son interrupteur sur ON.

Pourquoi P15:P16 ? Parce que nous utiliserons P16 comme TX et P15 comme RX pour la liaison série UART avec l’ESP8266.
Étape 3 — Ouvrir MakeCode

Créer un nouveau projet micro:bit

1. Ouvrez makecode.microbit.org.

2. Cliquez sur Nouveau projet.

3. Donnez un nom simple, par exemple Test WiFi ThingSpeak.

4. Une fois l’éditeur ouvert, regardez la colonne de blocs à gauche.

Vous devez voir les catégories habituelles : Base, Entrées, Musique, LED, Radio, Boucles, Logique, Variables…
Étape 4 — Ajouter l’extension ESP8266

Installer les blocs Cytron

1. Dans MakeCode, cliquez sur Extensions.

2. Dans la zone de recherche, saisissez CytronTechnologies/pxt-esp8266.

3. Sélectionnez l’extension ESP8266 de Cytron.

4. Une nouvelle catégorie de blocs liée à l’ESP8266 apparaît dans MakeCode.

Si les blocs ESP8266 n’apparaissent pas, arrêtez-vous ici : l’extension n’est pas correctement installée.
Étape 5 — Dire à la micro:bit où se trouve l’ESP8266

Initialiser la liaison série

Dans le bloc Au démarrage, ajoutez le bloc d’initialisation ESP8266.

TX = P16
RX = P15
Baudrate = 115200

Pourquoi ces valeurs ? Le câble Grove est branché sur P15:P16. P16 transmet vers le RX du module, P15 reçoit ce que transmet le module.

À obtenir : le programme sait désormais par quelles broches communiquer avec l’ESP8266.
Étape 6 — Vérifier que l’ESP8266 répond

Ne cherchez pas encore Internet

Ajoutez le bloc de test proposé par l’extension Cytron pour vérifier l’initialisation du module.

Si l’initialisation réussit, affichez par exemple ✓ sur la micro:bit. Sinon, affichez ✗.

✓ apparaît

La micro:bit et l’ESP8266 communiquent. Vous pouvez continuer.

✗ apparaît

Vérifiez P15:P16, le câble Grove, l’alimentation, l’interrupteur de la REKA:BIT et les broches P16/P15 dans le programme.

Étape 7 — Connecter le module au Wi‑Fi

Entrer le nom et le mot de passe du réseau

Ajoutez le bloc connect WiFi.

SSID = "Nom_du_reseau"
Mot de passe = "Mot_de_passe"

Le SSID est simplement le nom visible du réseau Wi‑Fi. Pour une formation, utilisez de préférence un point d’accès 2,4 GHz simple, sans portail captif.

Ne confondez pas : être relié physiquement à l’ESP8266 n’est pas encore être connecté au Wi‑Fi.
Étape 8 — Préparer ThingSpeak

Le professeur crée les comptes et les canaux

Avec vos deux comptes professionnels, vous pouvez répartir les 7 postes sur deux espaces ThingSpeak. Les élèves n’ont pas besoin d’utiliser leur adresse mail.

Compte enseignant ACompte enseignant B
Groupes 1 à 4Groupes 5 à 7

Pour chaque groupe : créez un canal distinct afin que chaque poste possède sa propre clé d’écriture et son propre graphique.

Étape 9 — Créer un canal ThingSpeak

Recette écran par écran

1. Connectez-vous à ThingSpeak avec le compte professeur.

2. Ouvrez Channels puis My Channels.

3. Cliquez sur New Channel.

4. Donnez un nom, par exemple Groupe 1 — Station connectée.

5. Activez Field 1 et nommez-le Valeur test.

6. Cliquez sur Save Channel.

7. Ouvrez ensuite l’onglet API Keys.

8. Repérez la Write API Key.

La Write API Key est la clé qui autorise l’objet à écrire dans ce canal. Ne publiez jamais vos vraies clés dans le dépôt GitHub.
Étape 10 — Premier envoi : une valeur fixe

Tester ThingSpeak avant le capteur

Dans MakeCode, utilisez le bloc d’envoi ThingSpeak fourni par Cytron.

Write API Key = "VOTRE_CLE"
Field 1 = 22

Pour le premier test, envoyez simplement 22. Cela évite qu’un problème de capteur vienne brouiller le diagnostic.

Étape 11 — Télécharger le programme

Envoyer le programme dans la micro:bit

1. Connectez la micro:bit à l’ordinateur par USB.

2. Cliquez sur Télécharger dans MakeCode.

3. Copiez ou transférez le fichier vers la micro:bit selon la méthode habituelle.

4. Laissez ensuite la REKA:BIT alimentée : le câble USB n’est pas nécessaire au transfert des données vers ThingSpeak, seulement pour programmer ou alimenter selon votre configuration.

Étape 12 — Vérifier le résultat

Regarder le graphique ThingSpeak

Revenez dans le canal ThingSpeak. Après l’envoi, la valeur 22 doit apparaître dans le graphique du Field 1.

La valeur apparaît

Bravo : UART, ESP8266, Wi‑Fi, Internet et ThingSpeak fonctionnent.

Rien n’apparaît

Vérifiez dans cet ordre : alimentation → initialisation ESP8266 → connexion Wi‑Fi → Write API Key → délai d’envoi.

Étape 13 — Seulement maintenant, ajouter un capteur

Remplacer 22 par une vraie mesure

Une fois la chaîne complète validée, remplacez progressivement la valeur fixe par une variable issue d’un capteur.

température = lire le capteur
Upload ThingSpeak
Field 1 = température

Ensuite seulement, ajoutez d’autres champs : humidité, pression, CO₂, luminosité, etc.

Principe de dépannage à conserver : on ajoute une difficulté à la fois.
À retenir

La méthode de diagnostic

1. Matériel→2. UART→3. Wi‑Fi→4. ThingSpeak→5. Capteur

Si l’on branche tout et programme tout en même temps, on ne sait plus où chercher lorsqu’une erreur apparaît. Le pas à pas sert autant à apprendre qu’à dépanner.

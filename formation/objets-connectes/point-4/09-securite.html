Point 4 · Sous-partie 9

Write Key, Read Key : ce qu’il faut protéger

Les clés n’ont pas toutes le même rôle. Comprendre la différence évite de publier par erreur une information sensible.

Deux clés, deux usages

Write API Key

Autorise l’objet à écrire des données dans le canal.

Ne jamais l’afficher dans une page GitHub publique.

Read API Key

Permet de lire les données d’un canal privé.

Si elle est placée dans un JavaScript public, elle est visible dans le code source.
Cas simple recommandé en formation

Canaux publics + données techniques anonymes

Pour de la température, de l’humidité, du CO₂ ou de la lumière sans donnée personnelle, un canal public permet au site GitHub Pages de lire les mesures sans Read API Key.

Public ne veut pas dire « données personnelles ». Ne publiez ni noms d’élèves ni informations sensibles.
Si les données doivent rester privées

GitHub Pages seul ne suffit pas à cacher une clé

ThingSpeak privé→serveur intermédiaire→page web

Le serveur garde la clé secrète. Une page HTML statique ne peut pas cacher durablement un secret envoyé au navigateur.

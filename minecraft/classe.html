MODULE 04

Organiser et piloter une classe

Une organisation claire évite que l’activité de construction prenne le pas sur l’apprentissage.

Multijoueur : héberger et rejoindre

EnseignantOuvre le monde
→

→
Code illustréÀ transmettre en classe

ÉlèvesJouer → Rejoindre
→
SauvegardePar l’hôte
  1. Sur le poste hôte, ouvrir un monde et activer le multijoueur ou choisir Héberger selon l’écran.
  2. Afficher le code de connexion dans le menu pause : les élèves saisissent les pictogrammes dans Rejoindre un monde.
  3. Pour une session hébergée sur un poste, conserver le monde ouvert ; les comptes doivent appartenir au même tenant Microsoft 365 et utiliser des versions compatibles.
  4. Vérifier que chaque élève possède les droits nécessaires. Ne pas donner le rôle Opérateur à toute la classe.
  5. À la fin, arrêter la construction, demander les traces et exporter le monde depuis le poste hôte.
Deux modes d’hébergement

Le mode hébergé par un joueur suffit pour un premier atelier. Minecraft Education propose aussi des serveurs dédiés persistants : leur installation, les droits inter-établissements et l’administration réseau doivent être validés avec le service informatique. Voir le guide serveurs dédiés.

Plan de classe proposé

Quatre îlots pour un monde partagé : terrain identique pour chaque groupe, allées non modifiables, consignes au point de départ. Délimiter physiquement ou avec les blocs spécifiques après un test en compte élève. Allow/Deny ne constituent pas à eux seuls des permissions individuelles par équipe.

Travailler à trois sur un ordinateur

Un pilote manipule ; un concepteur suit le plan et prépare les choix ; un testeur-documentaliste mesure, note les essais et contrôle les exigences. Rotation toutes les 10 à 15 minutes. Si le groupe compte deux élèves, réunir conception et tests.

Prudence

Certaines commandes exigent les droits d’opérateur et/ou l’activation des commandes. Les paramètres et leur libellé dépendent de la version. Faire un essai sur une copie. Ne pas désactiver les protections réseau pour résoudre une erreur de connexion.

TUTORIEL 01

Héberger un atelier multijoueur

  1. Sur deux postes, vérifier les versions et les comptes autorisés. Pour une session hébergée par un joueur, vérifier que les comptes relèvent du même tenant scolaire.
  2. L’enseignant ouvre sa copie du monde, choisit Héberger dans le menu de pause si nécessaire et présente le code en pictogrammes aux participants.
  3. Les élèves ouvrent Jouer puis Rejoindre un monde ; ils saisissent le code et rejoignent le point de départ. Attribuer le rôle Membre, pas Opérateur.
  4. Conserver le poste hôte actif. Si une connexion échoue, contrôler version, compte et réseau avec le service informatique ; tester d’abord avec un seul élève.
  5. Pour une activité qui doit rester accessible hors des heures de cours, étudier avec le service informatique un serveur dédié, ses autorisations, ses sauvegardes et son administration.
Résultat à vérifier
Deux élèves peuvent rejoindre, construire et quitter ; l’hôte exporte la production.

TUTORIEL 02

Protéger un chantier collectif

  1. Faire une copie du monde. Préparer les zones avec les droits World Builder et les blocs Allow, Deny ou Border si disponibles.
  2. Tracer les parcelles et les allées. Employer Deny pour les espaces à préserver, Allow pour les espaces constructibles dans un monde verrouillé ; vérifier la portée verticale de ces blocs.
  3. Tester avec un compte élève ordinaire : peut-il construire dans sa parcelle, casser un panneau de consigne, franchir la limite ? Adapter en conséquence. Ces blocs ne gèrent pas les droits par équipe à eux seuls.
  4. Si Classroom Mode est installé et compatible, connecter l’application à la session selon les instructions officielles. Utiliser sa carte et sa liste de joueurs pour repérer les élèves et les aider. Les paramètres intégrés au monde peuvent suffire.
Résultat à vérifier
Les élèves peuvent travailler dans les zones prévues et les consignes sont protégées.

Partie 1 • Fiche élève, chapitre 1

1. Les équipements du réseau

Comment deux ordinateurs peuvent-ils communiquer ?

Un réseau local relie des appareils proches, par exemple dans le collège. Le switch (commutateur) relie les appareils du même réseau. Le routeur relie des réseaux différents. Internet est un ensemble mondial de réseaux reliés entre eux.
Conseils et précisions pour l’enseignant

Faire suivre les câbles du doigt. Le PC décide si la destination est locale ou distante. Si elle est distante, il envoie les données à sa passerelle (routeur). Le switch transmet les trames en utilisant les adresses MAC. Une box peut réunir routeur, switch et Wi-Fi.

Correction de la fiche élève

réseau local
1.2 Le ____________ permet de relier deux réseaux différents.
routeur
1.3 Internet est un ensemble de ____________ interconnectés.
réseaux
1.4 Sur le schéma, écris le trajet de PC 1 vers PC 2.
PC 1 → S1 → PC 2
1.5 Écris le trajet de PC 1 vers PC 3.
PC 1 → S1 → Routeur → S2 → PC 3

2. L’adresse IP et le masque

Comment reconnaître le destinataire ?

Une adresse IP identifie une interface réseau, comme une adresse postale permet de joindre un destinataire. En IPv4, elle comporte quatre nombres de 0 à 255, séparés par des points. Avec le masque 255.255.255.0, les trois premiers nombres identifient le réseau et le dernier identifie l’hôte.

Testons deux adresses IP

Masque utilisé : 255.255.255.0

Pour ce masque : .0 désigne le réseau, .255 la diffusion. 254 adresses sont attribuables.

Conseils et précisions pour l’enseignant

Avec ce masque uniquement, l’adresse du réseau finit par .0 et l’adresse de diffusion par .255 : elles sont réservées. Les adresses .1 à .254 peuvent être attribuées. Ne pas attribuer deux fois la même adresse dans un réseau.

4 ; 0 ; 255
2.2 Pour 192.168.1.25 : partie réseau = __________ ; partie hôte = ____.
192.168.1 ; 25
2.3 192.168.1.40 et 192.168.2.40 : même réseau ? Justifie.
Non : 192.168.1 et 192.168.2 sont différents.
2.4 Propose une adresse libre du réseau 192.168.1.0.
Par exemple 192.168.1.50, si elle est libre.
2.5 Pourquoi 192.168.1.300 est-elle invalide ?
300 dépasse 255.

3. Masque de sous-réseau : méthode générale

Le masque comporte 32 bits : les 1 indiquent la partie réseau et les 0 la partie hôte. Pour calculer l’adresse réseau, on applique un ET logique entre l’IP et le masque : 1 ET 1 = 1 ; dans tous les autres cas, le résultat est 0. La notation /24 signifie 24 bits à 1.
MasquePréfixeExemple : IP 192.168.2.130Hôtes utilisables
255.0.0.0/8192.0.0.016 777 214
255.255.0.0/16192.168.0.065 534
255.255.255.0/24192.168.2.0254
255.255.255.128/25192.168.2.128126

Exemple détaillé : /25

Les trois premiers octets restent inchangés. On calcule le dernier octet :

IP (130)1 0 0 0 0 0 1 0
Masque (128)1 0 0 0 0 0 0 0
ET (128)1 0 0 0 0 0 0 0

Le réseau est 192.168.2.128/25 ; la diffusion est 192.168.2.255 ; les hôtes vont de .129 à .254. L’autre sous-réseau /25 va de .0 à .127, avec hôtes .1 à .126. Pour un sous-réseau classique de n bits hôte, il existe 2ⁿ − 2 adresses utilisables (exceptions /31 et /32 hors cours).

Méthode : calculer l’adresse réseau de chaque machine avec son masque. Dans nos exemples, les machines ont le même masque : si leurs adresses réseau sont identiques, elles sont dans le même sous-réseau.

Je complète et j’applique

3.1 Avec /16, 192.168.1.10 et 192.168.2.20 sont-elles dans le même sous-réseau ? Et avec /24 ?
Oui avec /16 (192.168.0.0) ; non avec /24.
3.2 Avec /25, calcule le réseau de 192.168.2.100 et celui de 192.168.2.130.
192.168.2.0 et 192.168.2.128 : deux sous-réseaux différents.
3.3 Combien d’hôtes peut-on adresser avec /25 ?
2⁷ − 2 = 126.

4. Adresses privées et publiques

Une adresse locale est une adresse utilisée sur un réseau local. Une adresse IPv4 privée appartient à une plage réservée aux réseaux internes : elle n’est pas routée sur l’Internet public. Une adresse publique peut être routée sur Internet si elle est attribuée et annoncée. Deux maisons peuvent utiliser la même adresse privée sans conflit, car leurs réseaux sont séparés. Dans un même réseau, deux interfaces ne doivent pas utiliser la même adresse.
Plage privéeExemple
10.0.0.0 à 10.255.255.25510.1.2.3
172.16.0.0 à 172.31.255.255172.20.1.5
192.168.0.0 à 192.168.255.255192.168.1.25

Exemple d’adresse publique : 1.1.1.1. Attention : toutes les adresses hors des plages privées ne sont pas publiques (127.0.0.1 désigne par exemple la machine elle-même). Une adresse locale peut aussi être publique : « local » décrit le contexte, « privé » décrit une catégorie d’adresses.

Je complète et j’applique

4.1 Pourquoi les deux PC du schéma peuvent-ils avoir la même adresse ?
Ils appartiennent à deux réseaux locaux séparés.
4.2 Classe 10.0.0.8, 172.20.1.5, 192.168.1.25 et 1.1.1.1.
Les trois premières sont privées ; 1.1.1.1 est publique.

5. La passerelle : communiquer entre réseaux

La passerelle par défaut est l’adresse de l’interface du routeur située dans le réseau local. Le terminal compare le réseau de destination au sien grâce au masque.

Destination locale : le terminal transmet les données directement au destinataire, via le switch. Destination distante : il transmet le paquet à sa passerelle, qui le dirige vers un autre réseau.

Sans passerelle correctement configurée, les échanges locaux restent possibles mais les réseaux distants ne sont généralement pas accessibles.

Je complète et j’applique

5.1 Quelle passerelle PC A doit-il configurer ?
192.168.1.1.
5.2 PC A veut joindre 192.168.1.20/24 : a-t-il besoin du routeur ?
Non, si les deux sont dans le même réseau local.
5.3 Que se passe-t-il si la passerelle est mal configurée ?
Les communications locales peuvent fonctionner, mais les réseaux distants ne sont généralement pas accessibles.

6. Les paquets de données et le protocole IP

Comment envoyer un fichier sans tout envoyer en un seul bloc ?

Notre histoire. Lina (PC 1, 192.168.1.10) veut envoyer « BONJOUR À TOUS » à Adam (PC 3, 192.168.2.20). Ils sont dans deux réseaux locaux différents, reliés par des routeurs. Leurs masques sont 255.255.255.0.

1. Découper. Imagine un livre trop gros pour une enveloppe : on peut envoyer ses pages dans plusieurs enveloppes. De même, les données d’un fichier sont réparties en petites unités. Ici : BON | JOUR | À | TOUS. Dans la réalité, on découpe des données numériques, pas forcément des mots. Les petits paquets permettent à plusieurs utilisateurs de partager une liaison.

2. Adresser. Comme sur une enveloppe, il faut indiquer qui envoie et qui doit recevoir. IP (Internet Protocol) ajoute un en-tête à chaque paquet : source 192.168.1.10, destination 192.168.2.20. Le reste transporte les données et les informations du protocole de transport. Les quatre paquets portent les mêmes adresses IP.

3. Acheminer. Lina compare les réseaux : 192.168.1.0 et 192.168.2.0 sont différents. Son ordinateur envoie donc le paquet à sa passerelle. Chaque routeur lit l’adresse IP de destination, puis choisit à quel voisin transmettre le paquet. Il n’a pas besoin de lire « BON ».

4. Recevoir. Adam reçoit les paquets séparément. IP permet de les adresser et de les acheminer, mais ne garantit ni leur arrivée ni leur ordre. Comment récupérer le message complet ? C’est la question suivante.

Explications pour le professeur

Faire jouer le rôle du routeur à un élève : lui donner une carte-paquet et une table. Il doit lire uniquement l’adresse de destination pour décider où transmettre la carte. Les numéros de morceaux du dessin sont pédagogiques, pas des champs de numérotation IP. La taille des paquets et les détails d’encapsulation ne sont pas exigés.

Correction de la fiche élève

6.1 Pourquoi diviser un fichier en plusieurs morceaux ?
Pour partager les liaisons et transmettre les données par petites unités.
6.2 Quelles sont les deux adresses présentes dans l’en-tête IP ?
Les adresses IP source et destination.
6.3 Quelle adresse le routeur utilise-t-il pour choisir le prochain saut ?
L’adresse IP de destination.
6.4 Entoure le contenu du paquet sur le schéma.
La zone verte : informations de transport et données.
6.5 IP garantit-il que tous les paquets arrivent ?
Non. IP assure l’adressage et l’acheminement, sans garantir la livraison.
Partie 7 • Fiche élève, chapitre 7

7. Pour comprendre : la fiabilité des échanges (facultatif)

Que se passe-t-il si un morceau du fichier se perd ?

La suite de notre histoire. Adam reçoit les morceaux 3 (« À »), 1 (« BON ») et 4 (« TOUS »). Le morceau 2 (« JOUR ») manque. Il ne peut pas encore retrouver le message complet.

Comment faire ? Si la communication utilise TCP, ce protocole suit les données reçues grâce à des informations de séquence. Adam confirme la réception de données (accusé de réception, ou ACK). Si des données manquent, TCP peut provoquer leur renvoi par Lina.

Exemple résolu : 3, 1, 4 reçus → 2 manquant → Lina renvoie 2 → TCP restitue 1, 2, 3, 4 → « BONJOUR À TOUS ». Les nombres sont ici des repères pédagogiques.

À retenir : IP achemine les paquets ; TCP, lorsqu’il est utilisé, assure une transmission fiable et ordonnée. Les détails de TCP sont facultatifs dans cette séquence.

Simulation : un segment perdu

Conseils et précisions pour l’enseignant

Faire jouer quatre élèves porteurs de cartes numérotées. Le destinataire annonce ce qu’il a reçu ; retenir la carte 2 puis la renvoyer. Les numéros 1 à 4 sont une simplification : TCP utilise des numéros de séquence d’octets et les ACK peuvent être cumulatifs.

8. Le routage et les pannes

Comment les paquets trouvent-ils un chemin ?

Reprenons le voyage du message. Lina est au PC 1, Adam au PC 3. Les switchs S1 et S2 relient les appareils de leurs réseaux locaux. Les routeurs A, B, C, D et E relient les réseaux entre eux.

Le routage, c’est quoi ? Imagine un trajet en train avec des correspondances. À chaque gare, on choisit la prochaine direction. De même, chaque routeur lit la destination du paquet et choisit le prochain routeur à l’aide de sa table de routage.

Exemple résolu : PC 1 → S1 → A → B → C → D → S2 → PC 3. A transmet à B, B à C, C à D ; D permet d’atteindre le réseau local d’Adam. Aucun routeur n’a besoin de connaître tout le trajet.

Et si B tombe en panne ? Après mise à jour des routes, un autre trajet est possible : PC 1 → S1 → A → E → D → S2 → PC 3. Mais si A tombe en panne, Lina ne peut plus sortir de son réseau : aucune autre sortie n’est représentée. Plusieurs chemins améliorent donc la résistance aux pannes, sans garantir que toute panne soit surmontable.

Simulation : une panne sur le réseau

Choisir un scénario.

Conseils et précisions pour l’enseignant

Expliquer que le chemin avec le moins de routeurs n’est pas toujours préféré : les règles et coûts de routage comptent. Le premier trajet est un exemple possible, non un chemin optimal calculé. La panne de B permet une alternative, celle de A coupe l’accès local.

Correction de la fiche élève

routage
8.2 Trace un premier trajet de PC 1 à PC 3 en passant par B et C.
PC 1 → S1 → A → B → C → D → S2 → PC 3
8.3 Le routeur B tombe en panne. Trace un autre trajet.
PC 1 → S1 → A → E → D → S2 → PC 3
8.4 Si A tombe en panne, PC 1 peut-il joindre PC 3 sur ce schéma ? Pourquoi ?
Non : A est la seule sortie du réseau de PC 1.
8.5 Pourquoi prévoir plusieurs chemins ?
Pour maintenir les communications si un chemin devient indisponible.

9. Routage : lire une table et choisir le prochain saut

Dernière étape de notre histoire : observons comment A prend sa décision. Pour cette étude, on utilise un schéma plus petit avec deux chemins possibles vers le même réseau d’Adam. Lina garde l’adresse 192.168.1.10 ; Adam garde 192.168.2.20.

Une table de routage, c’est quoi ? C’est un tableau de directions, comparable à un panneau routier. Chaque ligne indique un réseau de destination, le prochain saut (l’adresse du routeur voisin à contacter, ou « Direct » si le réseau est relié au routeur) et éventuellement un coût. Le coût est une valeur de préférence : à destination et critères comparables, le plus petit est préféré dans notre exemple.

Exemple guidé : A reçoit un paquet destiné à 192.168.2.20. Avec /24 (255.255.255.0), les trois premiers nombres identifient le réseau : 192.168.2.0. A cherche donc ce réseau dans sa table. Deux directions sont disponibles : B ou C. Nous allons comparer leurs coûts.

Les adresses 10.0.0.2 (B) et 10.0.0.6 (C) identifient les interfaces des voisins de A. Les deux petits réseaux /30 servent uniquement aux liaisons entre routeurs : il n’est pas nécessaire de savoir les calculer ici. B et C sont tous deux reliés au réseau d’Adam, 192.168.2.0/24.

Table de A : destinationProchain sautCoût
192.168.1.0/24Direct (LAN)0
10.0.0.0/30Direct (vers B)0
10.0.0.4/30Direct (vers C)0
192.168.2.0/2410.0.0.2 (B)2
192.168.2.0/24 (secours)10.0.0.6 (C)5
0.0.0.0/0Sortie amont (non représentée)—

Étape 1 — Trouver la destination : 192.168.2.20 appartient à 192.168.2.0/24. Les lignes 192.168.1.0 et 10.0.0.0 ne correspondent pas.

Étape 2 — Comparer : pour 192.168.2.0/24, B coûte 2 et C coûte 5. Comme 2 est inférieur à 5, A transmet à B (10.0.0.2). Attention : 10.0.0.2 est l’adresse du voisin, pas celle d’Adam. L’adresse IP de destination du paquet reste 192.168.2.20.

Étape 3 — Poursuivre : B est directement relié au réseau d’Adam et peut lui transmettre le paquet. Si B tombe en panne et que sa route est retirée, A utilise C (10.0.0.6, coût 5).

Étape 4 — Aucun réseau précis ne correspond ? Pour une autre destination, par exemple 203.0.113.25, A utilise la route par défaut 0.0.0.0/0 si elle existe. S’il n’existe aucune route adaptée, A rejette le paquet. En pratique, on choisit d’abord la route au préfixe le plus précis, puis on départage les routes comparables.

Je complète et j’applique

9.1 Quel prochain saut A choisit-il pour 192.168.2.20 ? Pourquoi ?
10.0.0.2 (B), route /24 de coût 2.
9.2 B est en panne et sa route est retirée. Quel prochain saut ?
10.0.0.6 (C), coût 5.
9.3 Que fait le routeur si aucune route ne permet d’atteindre le réseau de destination ?
Il ne peut pas transmettre le paquet vers cette destination et le rejette.
9.4 Une adresse ne correspond à aucun préfixe précis. Quelle route est utilisée si elle existe ?
La route par défaut 0.0.0.0/0.

10. Bilan à mémoriser

Switch : relie les équipements d’un réseau local. Routeur : relie plusieurs réseaux.

Adresse IP et masque : permettent d’identifier un équipement et son réseau. Passerelle : permet de joindre les autres réseaux.

IP : adresse et achemine les paquets. Routage : sélection du prochain saut à l’aide d’une table de routage.

Source : Académie de Toulouse, SNT, Protocoles TCP et IP, routage (2021). Schémas et activités créés pour la classe de troisième.

Situation de synthèse

Un PC 192.168.1.10/24, passerelle 192.168.1.1, envoie des données à un PC 192.168.2.20/24. Utilise le schéma et la table du chapitre 9.

10.1 Identifie le réseau du PC source, son adresse de diffusion et sa passerelle.
192.168.1.0 ; 192.168.1.255 ; 192.168.1.1.
10.2 Explique pourquoi le PC utilise sa passerelle et décris le trajet normal.
Le destinataire est dans un autre réseau. Le PC transmet via son switch au routeur A, qui choisit B, puis le réseau de destination.
10.3 Que se passe-t-il si B tombe en panne et que sa route est retirée ?
A sélectionne la route de secours via C si elle est disponible.
